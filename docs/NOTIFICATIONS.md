# 通知规则与外部推送

管理员在「管理 → 通知与告警」管理规则、渠道、模板和通知时区。触发的事件写入右上角通知中心，最近 100 条可见，已读状态按用户保存。站内事件和外部渠道的待发消息在同一事务提交。规则使用 Panel 已接收的监控数据，关闭浏览器后继续运行。

## 规则

每条规则有独立的名称、启用状态、监控项、服务器范围、重复提醒间隔、恢复开关、模板和渠道。选择全部服务器时包含后续新增节点。各节点分别计算，首次达到条件立即生成事件。重复提醒间隔为 0 表示每次异常只提醒一次，恢复后可重新触发。修改判断条件、范围或重新启用规则会重新建立判断状态。单纯修改模板、名称或接收渠道保留已有告警。

| 监控项 | 单位 | 判断方式 |
| --- | --- | --- |
| CPU、内存、文件系统使用率 | % | 滚动窗口平均值或所有样本严格大于阈值。文件系统按已用 /（已用 + 可用）计算 |
| 上行、下行速率 | MB/s，1 MB = 1,000,000 字节 | 对节点当前统计网卡的有效原始速率求和，再计算窗口 |
| 节点离线 | 分钟 | 从 Panel 判定离线起计时，在线时解除。Agent 正常停机沿用已有免告警语义 |
| 月流量用量 | GB 或周期额度百分比 | 当前计费用量达到阈值即触发，包括恰好相等。使用节点已应用的计费方向、账期和额度。无限额度节点可以使用 GB 规则，百分比规则显示「未设置额度」 |

窗口可设 1–60 分钟。按同节点、同指标的采样时间计算，每个有效样本权重相同。平均值回到阈值及以下时恢复。「窗口样本均超过阈值」在所有样本都回到阈值及以下时恢复。混合窗口保持已有告警并暂停重复提醒。点击规则的「查看状态」可区分告警中、数据不足、部分超阈值、正常和未设置额度。

完整窗口要求连续的有效数据覆盖窗口起点、窗口内至少有两个样本。间隔超过该组采样周期的 1.5 倍加 1 秒、指标无效或计费网卡过滤版本变化时，相关窗口重新积累。完整采集组使用 HTTP 上报周期，快速采集组使用对应传输模式的采样周期。Panel 忽略重复观测，过旧补报可用于建立窗口；超过正常上报周期加 5 秒的旧观测不会单独触发通知。重启或建立新的遥测会话后重新积累窗口，已触发的告警和上次提醒时间保存在数据库中。指标断报期间不会自动恢复，也不会按定时器发送旧指标提醒。

月流量无需等待统计窗口。累计数据带有缺口时，已观测到的用量达到阈值仍可触发；较低的不完整用量不会解除现有告警。节点确认新的周期或校准后，按随后收到的有效累计值重新判断。通知时区只用于格式化消息中的时间。节点计费时区仍然决定账期；数据库时间使用 UTC。

## 渠道和模板

- Telegram 使用 Bot Token 和目标 Chat ID（也支持频道用户名）。机器人需要能够向该会话发消息。
- Bark 使用 HTTPS 服务地址和设备 Key，可使用官方服务或自建服务。面板通过 JSON POST 推送，不把设备 Key 放在查询参数中。
- 每个渠道有独立名称和测试入口，按事件顺序投递。同一渠道等待重试时，其他渠道可以继续投递。保存凭证后仅显示是否已配置，留空保留已有凭证。更换接收目标会取消该渠道尚未发出的消息，更换 Bark 服务地址须重新填写 Key。备份恢复后必须重新填写外部渠道凭证，旧待发队列会清空。
- 「通用值班通知」在标题中显示节点和规则。首次告警给出指标、判断依据、判断值和阈值，持续提醒增加告警时长，恢复时给出总时长。内置「节点离线」规则默认使用「节点离线通知」，分别报告离线达到设定时长、仍离线和重新上线。三个阶段各有一个状态图标及事件时间，重复和恢复提醒由规则开关控制。
- 模板可分别编辑三个阶段的标题和正文。预览使用示例节点，内置离线模板使用 5 分钟触发、15 分钟提醒和 18 分钟恢复的样例。站内、Telegram 和 Bark 均使用同一份纯文本。可用变量为 `{rule}`、`{node}`、`{metric}`、`{basis}`、`{value}`、`{threshold}`、`{window}`、`{time}`、`{duration}`、`{duration_zh}`、`{state}`。`{duration_zh}` 显示中文时长（如「18 分钟」），`{duration}` 保留原格式（如 `18m0s`）。实例通知时区默认为 UTC，支持 Asia/Shanghai 等 IANA 时区。
- 渠道状态可在列表刷新。测试返回 202 表示已经入队。「渠道已接受」表示外部服务返回成功回执。网络错误、限流和服务端暂时错误退避重试，最多 5 次。每个渠道最多容纳 1000 条待发消息，队列满会记录投递失败，站内告警仍然可见。外部服务已经接受但响应丢失时，重试可能产生重复推送。

## 迁移与接口

原离线告警由内置「节点离线」规则承接，保留原开关、延迟和未到期的计时。通用设置 API 中的 `offline_alert_minutes` 继续与此规则同步。其他离线规则可以有独立的时长和服务器范围。

升级时，名称和全部文案仍与出厂值一致的旧「默认通知」更新为「通用值班通知」。仅当内置离线规则仍引用这份出厂模板且成功添加专版时，才切换到「节点离线通知」。已编辑的模板、独立副本和其他规则的绑定均保留。模板已达 32 份，或已有模板使用专版 ID 时，保留现有模板和绑定。新文案用于后续事件，历史通知和已入队推送保留生成时的内容。

SQLite 与 PostgreSQL 分别使用 0026 和 0005 迁移，启动时升级现有数据库。备份仍校验完整的迁移摘要，升级前的快照应通过与其 Schema 匹配的 Panel 版本恢复。渠道凭证使用数据库配套的私有密钥文件加密。管理员配置保存使用 revision 检测并发覆盖，凭证不会进入读取响应或审计内容。

| 管理员接口 | 用途 |
| --- | --- |
| GET /api/v1/settings/notifications | 查询配置、凭证配置状态、每渠道最近投递结果 |
| PUT /api/v1/settings/notifications | 按 revision 保存配置，可选提交需更新的凭证 |
| GET /api/v1/settings/notifications/rules/{id}/status | 查看规则覆盖节点和判断状态，每页 50 台，使用 after 游标 |
| POST /api/v1/settings/notifications/preview | 按指定时区预览三种消息 |
| POST /api/v1/settings/notifications/channels/{id}/test | 为已保存的渠道排入测试消息 |

站内通知读取和实时事件新增 title、event_kind 字段，message 保存正文。旧记录显示为节点离线通知。Viewer 及以上角色继续使用原有通知读取和标记已读接口。此功能复用 Telemetry v3 监控协议。
