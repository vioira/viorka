# 客户端订阅

订阅聚合明确选中的已发布托管服务，输出完整的 Mihomo YAML、sing-box JSON 或 Loon 配置。当前仅导出 VLESS TCP、REALITY、Vision 服务；Realm 是 TCP 中继，不直接生成客户端节点。当前未提供流量配额或设备识别。

编辑订阅使用独立工作区，左侧按节点或协议分组搜索和勾选服务，右侧即时显示已选服务并支持排序、移除。候选服务按搜索条件分页，每页最多 20 个。分组勾选只作用于已显示的服务，翻页或更换关键词均保留已选顺序。每个订阅最多包含 100 个服务，新选服务追加到末尾。退出未保存的编辑时要求确认。候选及订阅服务元数据的 `protocol` 字段表示实际代理协议，当前可导出的协议为 `vless`，不可用服务的协议为空。

每个订阅选择服务和应用规则。默认模板中，服务按所选顺序进入手动选择组，首个可用服务为默认项，DIRECT 也可选择；私有地址直连，其他流量进入选择组。配置使用系统 DNS，查询可能暴露给系统或网络的 DNS 提供者。输出不启用代理 UDP，Loon 将不支持的代理 UDP 回退设为 REJECT；Mihomo 的本机 mixed 端口可配置且不监听局域网。客户端是否启用系统代理、TUN 或 VPN 由客户端控制。Loon 链接用于导入**远程配置**，不是导入远程节点订阅。

管理员可维护全局应用规则：条件以忽略大小写的包含匹配或正则匹配 User-Agent，按顺序取第一个匹配规则；同一订阅只使用所选且已启用的规则。内置 mihomo、sing-box 和停用的 loon 规则；请按实际应用的 User-Agent 补充或调整，Loon 的默认条件未作未经验证的猜测。`?format=mihomo`、`?format=sing-box`、`?format=loon` 可显式指定该订阅已启用的格式。应用规则通过 `template_id` 引用配置模板，格式由模板决定。User-Agent 仅选择应用规则，不是设备身份或鉴权凭据。同格式存在多条规则时，显式 `format` 使用所选且已启用规则中顺序最靠前的一条及其模板。

订阅链接的路径包含独立随机凭证，面板只保存哈希，仅在创建或轮换时显示完整链接。轮换或吊销立即停止旧链接后续更新，但不会撤销客户端已下载的节点凭证。外网访问必须使用 HTTPS，部署者应配置反向代理不记录 `/api/v1/subscription-links/` 下的完整请求路径和查询，避免泄露凭证；响应禁用缓存。每个订阅最多保留最近 20 条有效链接访问记录，包括脱敏 User-Agent、匹配规则和结果；显式指定格式时不会伪称 User-Agent 匹配了规则。不保存 IP 或完整 URL。

每份订阅使用一个凭证。签发窗口提供客户端导入说明、自动识别或指定格式的 URL，以及本地生成的二维码。这些 URL 共用同一凭证，轮换或吊销会同时影响所有使用它的客户端。

列表按名称和服务状态或吊销状态在服务端筛选，再使用游标分页。“最近拉取”展示该订阅最近一次有效链接请求的结果和时间，点击可查看访问记录。“已下发”表示服务器成功生成配置。清除访问记录同时清除最近拉取摘要。

管理员管理全部订阅，operator 管理自己创建的订阅，viewer 可读取自己的订阅。每次拉取重新检查所有者仍启用、角色仍有权管理，且对所有仍存在的所选节点有导出权限；权限不足时整份配置失败。成功删除服务、节点或卸载引擎后，原选择永久失效；重新创建同名或同 ID 的服务不会自动重新加入，可在编辑订阅时明确重新选择。节点离线或服务停止不改变最后成功发布的连接信息；服务停用、缺少公网入口或等待恢复确认时暂不输出。没有适用服务时返回错误，不伪造空配置。

## 配置模板与输出处理

“配置模板”提供 Mihomo、sing-box、Loon 三个默认模板。模板编辑将正文、正则替换和 JavaScript 分为三个编辑区，旁侧可生成示例配置预览，修改后提示重新生成。管理员可直接编辑默认模板，或复制为自定义模板，再在应用规则中选择。模板正文是完整的 YAML、JSON 或 Loon 配置，可修改 DNS、代理组、分流规则及其它客户端配置。默认模板不能删除；自定义模板在没有应用规则引用时可删除。模板格式创建后固定，修改格式应创建新模板并更新应用规则引用。

保存使用版本号和引用数量检查并发冲突；已被规则引用的模板需确认影响，保存后关联订阅下一次拉取立即使用新内容。模板不改变节点端配置。

保存共享模板前，确认框按页列出选用了该模板已启用规则的订阅。同一订阅引用多个匹配规则时只列一次。可选择一份订阅比较当前版本与待保存版本的输出。比较沿用订阅所有者权限、发布状态、恢复隔离、客户端兼容性及服务顺序，使用编辑器填写的 User-Agent 和参数作为模板输入。比较针对指定模板，实际拉取仍按客户端匹配规则。节点连接地址、端口、UUID 和 REALITY 参数在执行模板脚本前均替换为示例值，保留服务名称及订阅本机端口。结果仅显示发生变化的行段，两侧各限 16 KiB，超出会标记截断。预览不会生成访问记录。

每个模板保留最近 10 个历史版本，默认模板也可恢复。在“配置模板”的“更多操作”中选择“版本历史”，检查回退影响并确认后，历史名称、正文、正则和脚本会保存成新版本。版本号继续递增，被替换的内容进入历史。回退沿用当前版本和规则引用数的并发检查，并记录审计。历史随备份保存，删除自定义模板会连同该模板的历史一起删除。

正文支持以下变量，替换时只处理模板原文，节点名称不会被再次当作变量执行：

| 变量 | 内容 |
| --- | --- |
| `{{proxies}}` | Mihomo 为 JSON 节点数组（有效 YAML）；sing-box 为逗号分隔的 JSON 出口对象，放入 `outbounds` 数组；Loon 为节点配置行 |
| `{{proxy_names}}` | 节点名称列表，不含直连 |
| `{{proxy_choices}}` | 节点名称与 `DIRECT` / `direct` 直连选项 |
| `{{default_proxy}}` | 首个可用节点名称 |
| `{{port}}` | 订阅中的 Mihomo 本机端口 |

Mihomo、sing-box 名称列表使用 JSON 数组，单个名称自带 JSON 引号；Loon 使用逗号分隔文本。节点及名称来自订阅实际选中的可用服务，并沿用权限与兼容过滤。

生成顺序为：填入节点变量 → 按顺序执行条件正则替换 → 执行 JavaScript → 校验输出语法。正则使用 Go RE2 语法，替换内容支持 `${1}` 等捕获组。条件参数名留空表示无条件执行，否则仅在链接参数存在且值完全匹配时执行。链接参数最多 16 个，名称为 1–64 位英文字母、数字、下划线或连字符，值最多 256 字节，不允许重复参数。

Loon 默认模板包含替换规则：参数 `support-x25519mlkem768=true` 时，正则 `(tls-profile=|fp=)chrome([,\r\n]|$)` 替换为 `${1}chrome147${2}`。当前系统生成的字段为 `tls-profile=chrome`，同时支持自定义正文中的 `fp=chrome`。

JavaScript 编辑区填写函数体，可读取 `config`（当前配置字符串）、`context.userAgent` 和 `context.params`（不含路由凭证及 `format` 参数），必须返回配置字符串。例如：

```javascript
if (context.params["support-x25519mlkem768"] === "true") {
  config = config.replace(/(fp=|tls-profile=)chrome(?=,|$)/gm, "$1chrome147");
}
return config;
```

脚本通过 Goja 执行，不提供网络、文件、系统命令或宿主对象接口；设置 100 毫秒中断和 128 层调用栈上限。模板正文上限 128 KiB、脚本 16 KiB、替换规则 32 条、输出 2 MiB。脚本错误、超时或输出语法错误会终止下发，并将访问记录标记为不可用；不记录脚本异常中包含的配置或凭证。

预览使用明确标记的示例节点，可输入 User-Agent 和链接参数，执行当前未保存内容的完整处理流程。语法校验包括 JSON 对象、单份 YAML 和 Loon 必要区块；具体客户端的字段语义及联网效果仍通过客户端验证。

模板管理接口为 `/api/v1/subscription-templates`，预览为 `POST /api/v1/subscription-templates/preview`。管理写入、删除和预览仅管理员可用，读取沿用订阅页面权限。SQLite 与 PostgreSQL 建库时直接创建订阅模板及版本历史表，备份包含两者。

## 兼容范围和验证

- sing-box JSON 使用新式 `local` DNS、选择组和 TUN 配置，目标为 sing-box 1.14 系列；其他版本和应用需要单独验证。
- [Mihomo 官方文档](https://wiki.metacubex.one/en/config/proxies/tls/)提示与 Xray 26.7.11 及以后版本的 REALITY 可能不兼容；这类服务及未知 Xray 版本不下发到 Mihomo。[sing-box 上游问题](https://github.com/SagerNet/sing-box/issues/4520)报告了与 Xray 26.9.8 及以后版本的握手兼容风险，也予以过滤。过滤是保守策略，不代表其余组合已完成客户端互通验证。
- Loon 输出遵循其 [VLESS 节点配置文档](https://nsloon.app/docs/Node/)，Loon 与具体 Xray 版本的 REALITY 兼容性仍需实际测试。
- 本地自动化测试不代表客户端配置导入、DNS 行为、真实网络连通性或各系统 TUN 已经实机验收。

## 从备份恢复

恢复数据库时原子吊销所有订阅凭证。每个托管引擎在节点管理者发起只读核对前均被隔离，Panel 不会自动把备份目标应用到节点。该核对要求配套 `engine.manage.v8` Agent，通过认证的任务回报当前托管配置；匹配最后成功发布的配置时自动记录节点现状，不一致时由同时拥有节点管理和导出权限的管理者查看脱敏差异并确认采用。新安装且未生成配置的引擎会报告空的托管状态，需核对后采用。原备份草稿保留，发生差异后需重新检查并保存草稿才能发布。Agent 明确确认引擎未安装时，相应旧服务选择失效。

节点配置不包含面板维护的公网入口：每个服务须由节点管理者确认或修正地址和端口后才可再次下发，确认不代表公网连通。恢复后需要签发新链接。核对和采用只修改 Panel 记录，不修改或重启节点。

管理接口见生成的 [OpenAPI](../api/openapi/openapi.yaml)：`/api/v1/subscriptions`、`/api/v1/subscription-rules` 和 `/api/v1/subscription-recovery`；公开拉取入口为 `GET /api/v1/subscription-links/{token}`。管理接口使用现有会话、角色和 CSRF 约束。

恢复差异预览按字段展示面板目标记录与节点当前配置，包括服务监听、REALITY 目标、出口、分流条件及规则顺序。凭证只提示变化，不返回原值。核对确认未安装后重新安装并成功发布的服务，也会列入公网入口确认列表；旧订阅选择仍须手动重新选择。

## 托管线路入口

选择入口时可按直连或中转筛选。同一落地的直连项和中转项各占一个位置，三个现有输出格式沿用各自的兼容性检查。中转引用由入口节点、Realm 实例、稳定线路 ID 标识。拉取时重新核对订阅所有者的权限、实际分发修订、该公网端点的自动 TCP 检测结果及落地连接参数。公网重测期间、失败、探测点不可用或端点授权失效时，从候选和后续拉取中排除此项。仅选择中转时，停用或删除线路会使该项停止输出。全部选项不可用时沿用现有空订阅错误。详情见[线路状态与恢复规则](NAT_AND_RELAY.md#托管-realm-单跳线路)。
