# 节点系统运行时长与费用配置交接

**交接状态：已在双仓工作区实现，待发布。** 涉及 `viorka` 控制平面、Web 和 `viorka-agent`。第一项交付是让管理员看到主机最近一次采集的运行时长；第二项是让管理员登记每期费用及实际到期时间。

## 节点字段与业务口径

| 字段 | 口径与约束 |
| --- | --- |
| 系统运行时长 | Linux 主机从本次开机到采样时刻的运行秒数。主机重启后重新计时，Agent 重启或管理连接重连后仍使用内核读数。连接状态单独展示。 |
| 价格 | 每个计费周期的总价。例如 `240 CNY / 两年` 表示两年合计 240 元。允许零价，空值表示价格未知。金额必须非负，按币种校验小数位，用精确金额存储。 |
| 货币 | 使用明确的货币代码，例如 CNY、USD、EUR、JPY。填写价格时，货币和周期必填。 |
| 计费周期 | 固定单选，依次为 **月、季、半年、两年、三年、四年、五年**，对应 1、3、6、24、36、48、60 个月。前后端使用同一白名单，无年付、自定义或自由输入入口。 |
| 到期时间 | 指节点租用的实际到期时刻，可单独设置、修改、清除，也可补录过去的时间。用户选择日期，后端按浏览器时区取当天 23:59:59，以 UTC 存储。 |

费用和到期时间由管理员维护，有节点查看权限的用户可读。清除价格时可以保留到期时间。到期后显示“已到期”及具体时间；续费后由管理员更新日期。到期标记仅影响展示，不触发停机、停服务、任务调度变更或自动顺延。

## Agent 采集与协议兼容

1. **基础 v3 契约。** Agent 在快速采样中读取 Linux `/proc/uptime` 的第一个数值。公网 IP 使用独立慢速调度，监控调度启动即安排首次检测，此后每 600 秒一次。现有 v3 快速样本校验要求运行时长与 `uptime_unavailable` 两者有其一。
2. **低频模式。** 将运行时长移到公网 IP 的采集节奏：启动采一次，此后每 10 分钟采一次。实时监控、页面访问及切换上报模式均不额外触发读取。每次成功采样携带实际采样时间。IP 查询超时仍可上报本轮有效运行时长；读取运行时长失败也不影响 IP 结果。
3. **兼容。** 通过能力协商启用低频上报。新旧双方未协商成功时沿用现有 v3 契约。协商成功后，两个慢速采样点之间的快速样本允许省略运行时长，只有实际读取失败才报告失败。Agent 声明 `node.uptime.slow.v1`，Panel 在 ready 中返回 `slow_uptime: true`。慢速读数位于 `public_ip[].uptime`，包含实际读取时间与秒数或错误码。见[协议说明](../api/agent/v1/TELEMETRY_V3.md#host-uptime)。

代码入口见 [Agent 快速采集](../../viorka-agent/internal/collector/telemetry_fast.go)、[Agent 慢速调度](../../viorka-agent/internal/connection/telemetry_schedule.go) 和 [Panel v3 语义校验](../protocol/v1/telemetry_semantics.go)。Agent 链接按两个仓库相邻检出解析。

## Panel 存储与接口

- 在 `nodes` 表保存最近一次有效的 `uptime_seconds` 和 `uptime_sampled_at`，两列同时为空或同时有值。仅接受通过节点身份、会话及样本时间校验的报告。按采样时间原子更新：更新的样本可以带来更小的运行秒数，重复或迟到样本不能覆盖新值。读取失败保留原值和原时间。旧 Agent 的高频上报在节点表写入端按 10 分钟节流。
- 指标历史接口按慢速运行时长的实际采样时间写入对应的 30 秒桶。重复和失败样本不新增运行时长记录。迟到读数可补入已提交的时间桶，保留该桶的其他指标。
- 费用字段和租用到期时间同属节点资产资料，初始均可为空。租用到期时间独立于注册凭证有效期。新增字段覆盖 SQLite、PostgreSQL 以及备份恢复路径。数据库实现约定见[存储文档](DATABASE.md)。
- 节点列表和详情直接返回持久化的运行时长、采样时间、费用及到期时间。管理员一次保存费用与续期配置，服务端校验角色、金额、币种、周期和时间，原子写入并记录审计。使用费用配置自身的并发条件，避免覆盖其他管理员刚保存的值，也避免 Agent 更新运行时长导致表单冲突。节点详情使用 `PATCH /api/v1/nodes/{id}/settings` 的 `billing` 组提交，并以 `expected_revision` 校验独立的费用版本。原费用专用 PUT 接口保留兼容。

## Web 呈现

| 位置 | 展示或操作 |
| --- | --- |
| 节点列表 | 连接状态下方显示运行时长。费用合并为一列，如 `240 CNY / 两年`；到期时间单列，窄屏优先展示日期。 |
| 节点详情 → 概览 | 展示运行时长。费用与续期卡片展示每期资费、折合月付成本与本地租约到期时间。月均费用按计费月数折算，日均估算按每月 30 天计算。运行时长使用最近的真实采样值，例如“12 天 3 小时”。离线或样本过期时标明“上次采样”及时间；从未取得有效样本显示“暂无数据”。采样达到 15 分钟即标为“上次采样”。 |
| 节点详情 → 设置 → 费用与续期 | 价格、货币、周期同组，到期时间可独立填写，共用一个保存按钮。费用未配置按免费展示，到期日期留空显示“永不过期”。保存失败保留输入并使用全局 Toast。并发冲突后重新读取，以最新版本为基础保留已编辑的费用组或到期时间，带入未编辑部分的最新值，核对后再保存。 |

## 验收用例

- **采集节奏**：首次启动取得样本；进入实时监控后，在下一个 10 分钟采集点前不再读取 uptime。验证 IP 超时、uptime 读取失败和不支持平台各自的结果。
- **数据可信性**：同一节点重复及乱序上报后，仍保留最新有效样本。主机重启后接收较小的新值。Panel 重启后仍可读取原值和时间，Agent 重连不会将运行时长清零。
- **版本组合**：覆盖新旧 Agent 与 Panel 的能力协商、旧契约降级、旧 Agent 高频上报节流，以及新模式下快速样本省略 uptime 的校验。约定协议后验证双仓生成物和同步检查。
- **费用与权限**：覆盖七种周期、非法周期、零价与空价、币种精度、仅设到期时间、清除及跨时区显示。验证非管理员写入被拒绝、并发编辑返回冲突、资产变更进入审计以及备份恢复后字段一致。
- **页面状态**：验收有数据、无样本、过期、离线、未设置、已到期及窄屏展示。到期节点的连接与代理服务仍按原规则运行。

## 本地验收记录

- Linux ARM64 容器运行真实 Agent 进程，完成 HTTP → WSS → HTTP 切换。双端新版、仅升级 Panel、仅升级 Agent 三种组合均通过。对照版本为 Panel `2c2ef9f`、Agent `cf7d41e`。双端新版另验证了 Panel 在模式切换后读回内核运行时长。
- 600 秒采集间隔使用可控时钟测试，覆盖启动、实时租约和降级。独立测试覆盖公网 IP 与运行时长分别失败、重复序号、迟到采样、主机重启后的较小读数以及基础 v3 节流。
- SQLite 和 PostgreSQL 17 使用隔离数据库验证了精确金额、费用并发更新、审计及快照恢复。Web 已验证按本地时区录入到期时间、保存失败保留草稿和冲突后重新读取。
- 页面验收覆盖 390、768、1024、1440 px 与浅深主题。未执行生产 VPS 部署或长稳测试。
