# 节点、引擎与服务开发设计

> 状态：已确认的设计基线，核心流程已实现，尚未完成全项验收。更新日期：2026-11-03。
> 本文记录 Q1–Q38 的产品决定及 Q39 的文档授权；目标条目不等于已交付。实现与验证边界见 [开发验收记录](ENGINE_SERVICES_VALIDATION.md)。用户确认本次先完成代码与本地测试，记录 Linux/systemd 和外部客户端实机验收缺口。

## 1. 范围与资源关系

```text
Node
├── sing-box Engine（0 或 1 个托管实例）
│   └── ProxyService[*]
├── Xray Engine（0 或 1 个托管实例）
│   └── ProxyService[*]
└── Realm Engine（0 或 1 个托管实例）
    └── RelayRule[*]
```

- 节点可以自由安装一种、两种或三种引擎；同种引擎不支持多实例或多版本同时运行。保留旧二进制用于恢复不等于同时运行旧版本。
- 引擎负责运行，服务表达代理入口或转发规则。安装引擎与创建服务是独立操作；先安装适用引擎，再创建服务，没有引擎时提供安装入口并保留已填写内容。
- 一个实例承载多个服务，共享进程与配置；引擎重启、升级和发布可能影响全部关联服务，执行前展示影响范围。
- 代理服务与转发规则是不同业务对象，按业务类型、已验证版本和能力筛选引擎，不将三种引擎视为任意可互换选项。
- 服务创建后固定所属节点和引擎。首版通过创建新服务、验证、停用旧服务完成替换，不提供原地切换或跨节点迁移。
- 仅完整管理 Viorka 部署的实例。第三方实例只读发现；发现同类第三方实例后阻止安装同类托管实例，但允许安装其他类型。不覆盖、停止或自动接管第三方服务。

Panel 负责授权、草稿、期望状态、任务、审计和展示；独立 Agent 负责本地探测、下载、进程监管、配置验证、应用、健康检查与回滚。浏览器仅连接 Panel，Panel 不通过 SSH 或本地远程系统命令绕过 Agent，也不承载代理业务流量。

## 2. 安装、版本与进程生命周期

- 首版引擎管理限定 Linux + systemd，支持 amd64、arm64；其他环境明确不可安装。此限制不声称现有 Agent 在其他环境不能运行。
- 维护经过适配验证的版本清单，默认推荐其中一个并固定版本。Agent 从指定发行源下载并校验清单中的摘要；下载失败可重试，不支持任意 URL、自定义二进制上传或自动追随最新版。
- 用户主动升级，显示影响范围，保留上一版本及配置用于失败恢复。具体版本、校验/重载命令和健康检查方法由适配验证确定，不在本文猜测。
- 安装成功仅代表二进制、版本、运行环境就绪；没有服务时保持已安装、未运行。首次成功应用有效服务配置后启动。
- 分别保存引擎运行意愿和服务启用状态。手动停止后，应用配置只更新、验证配置，不能自动启动；节点重启后也保持停止，明确启动才恢复。
- 删除或停用最后一个启用服务并应用成功后停止进程，保留安装。因没有启用服务而停止与用户手动停止必须能够区分，不能丢失手动停止意愿。
- 期望运行且有启用服务的引擎开机恢复；崩溃进行有上限、带退避的恢复，连续失败标记异常。Panel 失联不停止既有业务。
- 各引擎独立安装、启停、升级、卸载。有关联服务时也可卸载，确认弹窗默认保留 Panel 服务草稿和凭证，重新安装后需应用配置恢复；可选择删除全部关联服务。REST `delete_services` 仅用于卸载，默认 false，删除仅在 Agent 回报卸载成功后执行，同时释放服务端端口预留。保留服务时继续预留草稿端口；卸载期间禁止修改草稿，提交时校验草稿版本。需配套更新 Agent；旧 Agent 仍会拒绝卸载已应用服务的引擎。

## 3. 草稿、发布与状态

### 3.1 三种配置视图

| 视图 | 含义 | 修改方式 |
|---|---|---|
| 共享草稿 | 尚未执行的编辑，记录修改人与并发版本 | 保存时条件版本校验，冲突返回刷新提示，不静默覆盖 |
| 已提交期望快照 | 点击应用后为任务固定的不可变配置 | 新修订，不改写历史；与 Task 原子持久化 |
| 节点确认状态 | Agent 实际确认的配置版本、进程状态和健康结果 | 校验身份、任务、attempt、资源和修订后更新 |

草稿不是已提交 Desired，Desired 不是 Observed。手动停止状态下配置已应用也不代表进程在运行；外部连通另行表示。

### 3.2 发布流程

1. 保存服务修改只更新共享草稿，允许同引擎多项修改合并后应用。
2. 点击应用时校验权限、在线状态、版本、端口和能力，展示影响范围；需要重启或其他中断业务的操作须确认。
3. 在事务内校验草稿版本、领取引擎变更资格，并提交不可变引擎级配置修订、任务和必要审计。只派发已提交任务；网络访问不放在事务内。
4. Agent 验证任务关联和能力，按实际版本生成配置，进行本地端口及配置预检。预检失败不替换现有配置。
5. 依运行意愿应用配置；运行中的实例按实测能力重载或重启，不承诺零中断。停止中的实例保持停止。
6. 上报配置与运行状态；运行时应用后的健康检查失败尝试恢复上一份可用配置。回滚失败明确标记异常，不报告成功。
7. 任务完成只更新该任务对应快照，不能清除提交后新增的草稿编辑；迟到回报不能覆盖新状态。

同引擎安装、升级、发布、回滚和启停等变更串行。存在未结束的变更任务时拒绝新的执行操作，不形成等待其他任务完成的操作队列；仍允许保存草稿。不同引擎可以独立执行，但共享节点端口分配和冲突检查。

离线时允许编辑草稿，拒绝新提交安装、手动应用、启停、升级、卸载等执行操作。共享协议配置编辑可在离线期间更新引擎目标，不创建执行任务；上线后由 Gateway 比较目标与已确认版本并自动应用最新目标，详见 [协议配置](PROTOCOL_PRESETS.md)。提交后断线保留任务及真实状态；超时结果可能未知，重连后先核对 Observed 和本地执行记录，不能盲目重试副作用。任务采用至少一次投递、Agent 幂等执行及最终确认，ack 不等于完成。

### 3.3 停用、删除和恢复

- 停用保留服务配置及 Viorka 端口分配，成功应用后停止实际监听。再次启用仍须检查外部进程占用；分配记录不能阻止第三方占用系统端口。
- 已部署服务删除后标记待删除，应用成功才最终移除并释放端口分配；失败保留记录和实际状态，应用前可以撤销。未部署草稿可直接删除；已进入在途快照的服务不能按纯草稿处理。
- 支持恢复上一份成功配置：展示差异并确认，生成新修订和新任务，重新检查端口、版本能力，不修改历史。
- 已成功更换的旧凭证不得因恢复历史配置而重新启用。恢复时使用当前有效凭证，无法兼容则阻止恢复；这条规则优先于按历史配置原样恢复。
- 凭证更换尚未成功时，不能声称旧凭证已撤销；发布失败仍如实呈现实际有效凭证，结果未知则先调和。

## 4. 业务配置与凭证

### 4.1 sing-box 与 Xray

首个代理协议为 VLESS + TCP + REALITY，先 sing-box 后 Xray。每个服务首版只有一组客户端凭证；系统生成 UUID 与 REALITY 密钥，普通编辑不更换。独立“更换凭证”操作经确认后随配置应用生效，并提醒重新分发连接信息。

结构化表单是配置权威来源，Agent 生成、验证配置；可脱敏查看最终配置，不提供整份原生配置编辑或导入。REALITY 握手目标地址、端口及允许的服务器名称必须明确配置，不自动挑选第三方目标。Agent 在发布前执行必要的 DNS、连接、TLS 检查，失败保留原配置并提供安全错误原因。

常规链接和二维码仅来自节点已确认应用的配置，且要求有明确对外入口。首次成功应用前禁用；有待应用修改时继续展示当前生效版本并标注。手动停止、离线或结果未知时须同时展示状态，不把已有连接参数解释为当前可用证明。

REALITY 私钥不提供常规查看或导出。UUID、密钥、完整链接不得进入 Toast、日志、SSE 或普通任务详情。敏感配置静态加密，密钥与数据库分离；凭证查看/导出单独授权，不能依靠隐藏按钮控制。

### 4.2 Realm

首版一条规则对应一个本地 TCP 监听地址、端口和一个目标地址、端口；目标可为 IP 或域名。之后扩展 UDP，不包含多目标、负载均衡、故障切换和自动链路编排。

配置错误、端口冲突和明确自循环阻止发布。目标探测失败时说明风险，允许用户明确确认后部署；此例外仅针对普通转发目标暂不可达，不放宽 REALITY 必要预检。Realm 部署成功不代表目标可达，目标探测结果单独展示。

## 5. 网络、端口和健康

- 本地监听与对外连接入口分开建模；可选择已登记公网映射或手工登记映射信息。缺少公网入口允许保存、部署，但不生成声称可用的客户端链接。
- 客户端使用需要直连公网入口或已有 TCP 映射；首版不自动打洞、不修改服务商映射、不自动创建中转链路。出口公网 IP 不能直接当作入站可达地址。
- 所有引擎与服务共享节点级端口检查，包含监听地址、通配绑定、IPv4/IPv6、TCP/UDP、已分配与实际占用。数据库约束/受控事务防止并发冲突，Agent 执行前再次检查。
- 展示配置是否应用、引擎是否运行、本地健康和外部连通结果，保留探测时间。进程或监听正常不证明公网可达。
- 首版交付验收必须使用真实外部客户端完成连接；产品没有外部探测能力时显示外部连通未验证，不伪造自动探测结果。

## 6. 权限、审计与界面约束

| 能力 | 首版权限目标 |
|---|---|
| 引擎安装、升级、卸载 | admin，并验证目标资源权限 |
| 授权节点的服务管理、配置应用、引擎启停 | operator/admin，并验证目标资源权限 |
| 脱敏状态与配置查看 | 获授权的 viewer/operator/admin |
| 客户端凭证查看与导出 | 单独授权，不由只读角色隐式获得 |

授权在 Panel 服务端执行；当前实例级角色不代表已经具备节点作用域与独立凭证权限。变更操作保留操作者、资源、修订、任务及安全结果摘要，禁止敏感载荷进入审计。

首版提供有界、脱敏的引擎运行日志和安装、发布、恢复任务记录，默认关闭访问日志，不承诺逐服务流量统计。失败应说明原因和恢复办法，不能吞错或伪造成功。

后续 UI 实现遵循仓库 Arc 与 Tailwind 规范，请求结果使用应用唯一全局 Toast stack；失败保留表单、列表、弹层和输入。待应用、待删除、离线、未知和异常等持久业务状态属于页面内容。没有适配的能力明确禁用；键盘、390/768/1024/1440px、浅深主题及弹层内提示均纳入验收。

## 7. 当前代码事实与实现差距

以下为 2026-11-03 工作区核查结果，不把表、接口或协议字符串当作业务实现。

| 范围 | 已有事实 | 开发前须补齐 |
|---|---|---|
| 数据模型 | [初始迁移](../migrations/0001_init.up.sql) 有 engines、proxy_services、relay_rules、config_revisions、deployments；engines 唯一键为 `(node_id,name)` | 共享草稿版本、运行意愿、待删除、有效凭证与撤销约束、引擎级变更互斥、端口并发约束及对应迁移 |
| 多引擎 | 唯一键允许不同类型各一条，但不能表达同类型多个 observed/managed 实例 | 保持托管单实例约束；第三方发现可能有多条事实，须明确只读探测快照表达，不能静默合并或误标为可接管 |
| Panel 业务 | [proxy](../internal/proxy/doc.go)、[orchestrator](../internal/orchestrator/doc.go) 为占位包 | 服务用例、配置编排、授权、原子发布、恢复及 HTTP/SSE 适配 |
| 任务 | [通用创建入口](../internal/scheduler/tasks.go) 仅接 node.inspect；[存储任务实现](../internal/storage/tasks.go) 另有 traffic.calibrate | 引擎操作白名单、类型化参数/结果、资源互斥及安全重试；不能沿用只读任务的重投假设 |
| 协议 | [Schema](../api/agent/v1/envelope.schema.json) 有通用 task.dispatch 和配置消息结构，operation 为字符串 | 新操作专用 Schema、示例、能力协商、兼容性及任务/attempt/engine/revision 关联验证 |
| Agent | 独立仓库 `internal/runtime/engine.go` 只有公共接口；`internal/runtime/{singbox,xray,realm}/doc.go` 与 `internal/supervisor/doc.go` 为占位 | 下载校验、三个适配器、systemd 监管、配置生成验证、运行意愿、本地执行持久化与恢复 |
| 权限与 Secret | [任务中心](TASK_CENTER.md) 记录现有实例级角色；[数据库设计](DATABASE.md) 要求配置加密 | 节点资源授权、独立凭证权限、敏感字段加密及轮换、历史恢复不得复活旧凭证 |
| Web | 引擎与服务尚无端到端管理交付 | 真实 API、草稿/生效状态、任务结果、错误和能力禁用，不以静态原型替代实现 |

当前 `deployments.status` 枚举不能单独表达“配置已应用但按用户要求停止”及独立外部连通状态，需要分开表达；不应把它们全部压入 healthy/failed。

已发布迁移不能原地改写，后续采用新增迁移并验证旧库升级、备份恢复。本文不新增 SQL、API 或协议字段；具体 REST 路径、DTO 和错误码在实现阶段从路由注册生成 OpenAPI，不手写生成文件。协议仍以 `api/agent/v1` 为唯一权威源，按 [双仓库策略](REPOSITORIES.md) 固定版本同步 Agent。

- [ ] 服务端覆盖未认证、角色限制、跨节点/资源越权、凭证单独授权与敏感信息脱敏。

新增独立 VLESS 协议预设管理。现有节点服务可以从支持的预设填入草稿；保存与应用仍是独立步骤。完整字段、引用限制及 API 见 [协议预设](PROTOCOL_PRESETS.md)。本次不扩展 Agent 的 TLS、XHTTP、WebSocket 或自动证书能力。

对外入口地址和端口仅用于面板生成连接链接，不进入 Agent 配置。应用草稿时，实际引擎命令与已确认目标一致则只更新面板发布快照，返回 HTTP 200 / local_only=true；不创建任务、不增加节点修订号。监听、协议、出口或分流变化仍返回 202 并下发任务；未确认或失败的目标仍需正常同步。

### 引擎状态展示

引擎查询返回 `last_error`，取最新引擎操作的错误码；成功核对后清除旧错误的展示。安装或核对的失败独立于配置目标的 `sync_error`，没有已发布配置也能显示归属冲突。

三种引擎统一区分未安装、安装待确认、运行状态与归属冲突。未知、异常和归属冲突时禁止启动、卸载和发布，保留核对入口；离线显示状态待确认。草稿版本与操作修订分别展示，不比较两个计数器；修订 0 显示节点尚未确认。发布使用已保存草稿，有本地未保存修改时禁用发布。审查界面不预报修订号或声称 Agent 已完成预检。
